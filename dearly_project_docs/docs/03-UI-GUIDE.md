# 03. UI 구현 지침

## 1. 디자인 방향
Dearly는 영어 일기를 쓰는 학생이 편안함과 응원을 느끼는 따뜻하고 차분한 웹 서비스다. 화면은 과하게 유아적이거나 게임처럼 만들지 않는다. 부드러운 여백, 둥근 카드, 읽기 쉬운 글자, 따뜻한 강조색을 사용한다.

UI 참고 이미지가 별도로 전달되면 해당 이미지의 레이아웃·색상·타이포그래피를 우선 분석해 반영한다. 참고 이미지가 없는 경우 이 문서의 기본 가이드를 따른다.

## 2. 색상 가이드
아래 값은 초기 제안이며 디자인 일관성을 위해 CSS 변수로 관리한다.
- 배경: 따뜻한 아이보리 `#FAF8F4`
- 카드: 흰색 `#FFFFFF`
- 기본 글자: 짙은 차콜 `#34343A`
- 보조 글자: 부드러운 회색 `#777780`
- 주요 강조: 차분한 라벤더 `#8E82C8`
- 보조 강조: 연한 라벤더 `#F0EDFA`
- 성공: 읽기 쉬운 녹색 계열
- 오류: 충분한 대비의 붉은색 계열

색상만으로 오류·성공을 구분하지 말고 텍스트와 아이콘 또는 설명을 함께 제공한다.

## 3. 레이아웃
- 본문 최대 너비는 약 760px로 설정하고 화면 중앙에 배치한다.
- 모바일에서는 좌우 16~20px 여백을 확보한다.
- 각 기능은 카드 단위로 구분한다.
- 카드 간 간격은 충분히 확보해 시각적으로 답답하지 않게 한다.
- 상단 브랜드와 일기 작성 영역이 첫 화면에서 쉽게 인식되도록 한다.
- 피드백 목록은 페이지 최하단에 둔다.

## 4. 타이포그래피
- 한글 본문은 시스템 기본 산세리프 계열을 우선 사용한다.
- 영어 교정문은 읽기 편한 글꼴과 줄 간격을 사용한다.
- 제목, 설명, 결과 본문 사이에 명확한 위계가 있어야 한다.
- 본문 줄 간격은 대략 1.6 이상을 권장한다.
- 작은 글씨도 충분히 읽을 수 있는 크기와 대비를 유지한다.

## 5. 컴포넌트
### 일기 입력 카드
- 제목과 짧은 사용 안내
- 넓은 textarea
- 글자 수 카운터
- 명확한 주요 버튼
- 로딩 시 버튼 내부 문구 또는 인접 상태 텍스트 변경

### 결과 카드
- 교정문은 원문과 시각적으로 구분한다.
- 수정 설명은 짧은 목록으로 표현한다.
- 영어 칭찬은 별도 강조 카드 또는 부드러운 배경 영역에 표시한다.
- 결과가 오기 전에는 빈 결과 패널을 과하게 노출하지 않는다.

### 피드백 영역
- 화면 하단에 작성 폼을 먼저, 목록을 그 아래 배치한다.
- 공개 목록임을 입력란 가까이에 안내한다.
- 목록 항목은 카드 또는 구분선이 있는 리스트로 표시한다.
- 최신 항목이 맨 위에 오도록 한다.

## 6. 반응형
- 768px 이하에서는 본문 폭을 100%로 사용하고 카드 여백을 줄인다.
- 버튼은 모바일에서 충분한 터치 영역을 확보한다.
- 가로 스크롤이 생기지 않도록 한다.
- 긴 영어 문장과 URL이 레이아웃을 깨뜨리지 않도록 `overflow-wrap` 등을 사용한다.

## 7. 접근성
- 모든 textarea와 버튼에 명확한 이름을 제공한다.
- 포커스 표시를 제거하지 않는다.
- 본문과 배경의 명도 대비를 확보한다.
- 오류는 해당 입력 영역과 연결해 알린다.
- 상태 메시지에는 `aria-live="polite"` 또는 적절한 역할을 사용한다.
- 의미 전달을 위해 이모지에만 의존하지 않는다.

## 8. 금지 사항
- 자동 재생 애니메이션이나 과도한 모션
- 깜빡이는 효과와 과도한 그라데이션
- 작은 글씨와 낮은 대비
- 실제 기능이 없는 버튼·메뉴
- 로그인·회원가입 UI
- 임의의 사용자 프로필·랭킹·점수 UI
