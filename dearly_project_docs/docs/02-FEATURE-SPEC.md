# 02. 기능 상세 구현 명세

## 1. 화면 구성 순서
한 페이지에서 다음 순서로 위에서 아래로 배치한다.
1. 브랜드 영역: Dearly, 짧은 환영 문구
2. 일기 작성 카드: 사용 방법, 영어 일기 입력란, 글자 수, 교정 버튼
3. 결과 영역: 교정문, 수정 설명, 영어 칭찬
4. 피드백 작성 카드: 의견 입력란, 공개 안내, 전송 버튼
5. 피드백 목록: 최신순 전체 목록

## 2. 일기 교정 동작
### 입력
- textarea의 최대 길이는 5,000자다.
- 글자 수를 `현재 글자 수 / 5,000`으로 표시한다.
- 앞뒤 공백을 제거한 결과가 비어 있으면 API를 호출하지 않는다.
- 입력 언어는 영어를 권장하며, 한국어 등 다른 언어가 입력된 경우 서버는 지원 범위를 안내하거나 AI에 영어 일기인지 확인하도록 요청한다.

### 처리
- 제출 직후 버튼을 비활성화하고 로딩 문구를 표시한다.
- 서버는 문자열 여부, 공백 여부, 길이를 다시 검증한다.
- 서버가 OpenAI에 문법 교정만을 위한 지시문과 사용자 원문을 분리해 전달한다.
- 사용자 원문에 포함된 지시문은 시스템 지시를 덮어쓰지 못하는 데이터로 취급한다.
- AI는 원문 의미를 보존하고 수정 설명은 한국어, 칭찬은 영어 한 문장으로 반환한다.
- 응답 필드가 누락되거나 잘못된 형식이면 서버 오류로 처리한다.

### 결과 표시
- `Corrected diary` 영역에 교정문을 표시한다.
- `What changed` 영역에 최대 5개의 수정 설명을 표시한다.
- `A little cheer` 영역에 영어 칭찬 한 문장을 강조해 표시한다.
- AI 응답은 `textContent` 등 안전한 텍스트 방식으로 표시한다.
- 새 요청 전까지 이전 결과를 유지하거나 명확히 초기화한다. 사용자가 입력한 원문은 실패 시 보존한다.

## 3. 피드백 등록
- 입력값: `message` 문자열
- 최소 유효 조건: trim 후 1자 이상
- 최대 길이: 1,000자
- 사용자 이름·이메일·학번 필드는 만들지 않는다.
- 제출 시 중복 클릭을 막는다.
- 성공 시 입력란을 비우고 최신 목록을 새로 조회한다.
- 실패 시 입력 내용을 유지하고 재시도 안내를 표시한다.
- 피드백 입력창 주변에 “등록한 의견은 다른 사용자에게 공개돼. 이름, 연락처 등 개인정보는 적지 마.”라는 취지의 안내를 둔다.

## 4. 피드백 목록
- 페이지 최초 로드 시 목록을 조회한다.
- 정렬 기준은 `created_at DESC`다.
- 페이지네이션 없이 모든 피드백을 반환한다. 다만 Supabase/서버 응답 크기 한도와 운영상 성능 문제가 발생하면 사용자 승인 후 페이지네이션으로 변경한다.
- 각 항목에는 내용과 사람이 읽기 쉬운 날짜·시간을 표시한다.
- 데이터가 없으면 “아직 등록된 피드백이 없어. 첫 의견을 남겨줘!”와 같은 빈 상태를 표시한다.
- 조회 실패 시 목록 영역에 오류와 다시 불러오기 버튼을 표시한다.

## 5. 오류 상태 문구 예시
| 상황 | 사용자 안내 |
|---|---|
| 빈 일기 | 영어 일기를 먼저 작성해 줘. |
| 일기 글자 수 초과 | 일기는 5,000자 이내로 작성해 줘. |
| AI 요청 실패 | 지금은 교정 결과를 가져오지 못했어. 잠시 후 다시 시도해 줘. |
| 빈 피드백 | 피드백 내용을 입력해 줘. |
| 피드백 길이 초과 | 피드백은 1,000자 이내로 작성해 줘. |
| 저장 실패 | 피드백을 보내지 못했어. 입력 내용은 유지했으니 다시 시도해 줘. |
| 목록 조회 실패 | 피드백 목록을 불러오지 못했어. 다시 시도해 줘. |
| 서버 설정 오류 | 서비스에 일시적인 문제가 있어. 잠시 후 다시 이용해 줘. |

## 6. 로딩 및 중복 요청
- 일기 교정 중 교정 버튼 비활성화
- 피드백 전송 중 전송 버튼 비활성화
- 목록 새로고침 중 로딩 상태 표시
- 가능하면 AbortController 또는 서버 타임아웃을 적용해 오래 걸리는 요청을 관리한다.
- 실패 시 버튼을 다시 활성화한다.
