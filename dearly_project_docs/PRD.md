# Dearly — 제품 요구사항 정의서(PRD)

- 문서 버전: 1.0
- 제품명: Dearly
- 제품 유형: 학생 대상 영어 일기 문법 교정 및 응원 서비스
- 플랫폼: 반응형 웹
- 로그인: 없음

## 1. 제품 개요

Dearly는 영어 일기를 쓰는 학생이 자신의 글을 부담 없이 점검하고, 작은 성취감을 느끼도록 돕는 서비스다. 사용자가 영어 일기를 입력하고 교정 요청을 보내면 AI가 문법과 자연스러운 표현을 다듬어 준다. 결과에는 교정된 문장과 주요 수정 이유, 영어로 된 따뜻한 칭찬 한마디가 포함된다.

서비스 하단에는 누구나 로그인 없이 남길 수 있는 피드백 작성 영역과 전체 피드백 목록이 있다. 제출된 피드백은 Supabase에 저장되고 최신순으로 표시된다.

## 2. 해결하려는 문제
- 영어 일기를 쓴 뒤 문법이나 표현이 맞는지 혼자 판단하기 어렵다.
- 틀린 부분만 지적받으면 영어 쓰기에 대한 자신감이 떨어질 수 있다.
- 학생이 서비스 사용 경험이나 개선 의견을 간단히 전달할 통로가 필요하다.

## 3. 대상 사용자
- 주요 사용자: 영어 일기 쓰기를 연습하는 학생
- 사용 환경: 모바일 또는 데스크톱 웹 브라우저
- 기술 숙련도: 별도 설명 없이 입력·버튼 중심으로 사용할 수 있어야 함
- 가입 요구: 없음

## 4. 핵심 사용자 흐름

### 4.1 영어 일기 교정
1. 사용자가 Dearly 첫 화면에 접속한다.
2. 영어 일기 입력란에 글을 작성한다.
3. `내 일기 교정하기` 버튼을 누른다.
4. 서버가 입력값을 검증하고 OpenAI API에 교정 요청을 보낸다.
5. 화면에 교정 결과, 주요 수정 설명, 영어 칭찬 한마디를 표시한다.
6. 사용자는 결과를 읽고 원문을 수정하거나 다시 요청할 수 있다.

### 4.2 서비스 피드백
1. 사용자가 화면 하단의 피드백 입력란에 의견을 작성한다.
2. `피드백 보내기`를 누른다.
3. 서버가 입력값을 검증하고 Supabase에 저장한다.
4. 성공 안내를 표시하고 최신순 피드백 목록을 갱신한다.
5. 로그인이나 계정 생성은 요구하지 않는다.

## 5. 기능 요구사항

### FR-01. 영어 일기 입력
- 사용자는 영어 일기를 여러 문장으로 입력할 수 있어야 한다.
- 입력란은 모바일에서 사용하기 편한 충분한 높이를 가져야 한다.
- 공백만 입력한 경우 제출을 막고 안내 문구를 표시한다.
- 최대 입력 길이는 5,000자다.
- 입력 글자 수를 표시한다.

### FR-02. AI 문법·표현 교정
- 사용자가 교정 요청을 보내면 서버가 OpenAI API를 호출한다.
- AI는 원래 의미와 사실을 임의로 바꾸지 않는다.
- 문법, 철자, 문장부호, 어색한 표현을 자연스럽게 교정한다.
- 학생의 학습을 위해 주요 수정 사항을 한국어로 간결하게 설명한다.
- 결과는 최소한 다음 항목을 포함한다.
  - 교정된 영어 일기
  - 주요 수정 설명(최대 5개)
  - 영어로 된 따뜻한 칭찬 한마디
- 원문이 이미 자연스럽다면 불필요하게 바꾸지 않고 잘 쓴 부분을 인정한다.
- AI 결과를 JSON 형식으로 받거나 서버에서 검증 가능한 구조로 변환한다.
- API 키는 서버에만 둔다.

### FR-03. 칭찬 문구
- 칭찬은 영어 한 문장으로 제공한다.
- 구체적이고 따뜻하며 학생을 존중하는 표현을 사용한다.
- 점수, 등급, 비교, 과장된 평가를 사용하지 않는다.
- 예: “You did a wonderful job expressing your thoughts today!”

### FR-04. 피드백 등록(로그인 불필요)
- 이름·이메일·학번 없이 피드백 내용만 제출할 수 있다.
- 피드백 최대 길이는 1,000자다.
- 공백만 입력한 피드백은 저장하지 않는다.
- 제출 성공 시 Supabase에 저장한다.
- 사용자는 등록 성공 여부를 확인할 수 있다.
- 중복 클릭으로 같은 요청이 여러 번 전송되지 않도록 처리한다.
- 공개 목록에 표시된다는 사실과 개인정보를 적지 말라는 안내를 입력란 근처에 표시한다.

### FR-05. 전체 피드백 목록
- 화면 하단에 저장된 피드백을 모두 목록으로 보여준다.
- 최신 작성 순(내림차순)으로 정렬한다.
- 각 항목에는 피드백 내용과 작성 시각을 표시한다.
- 목록이 비어 있으면 빈 상태 안내를 표시한다.
- 목록 조회 실패 시 재시도할 수 있는 오류 안내를 표시한다.
- 별도 로그인이나 작성자 프로필을 표시하지 않는다.

### FR-06. 오류 및 상태 메시지
- 일기 입력 오류, AI 요청 실패, 네트워크 오류, 피드백 저장 실패, 피드백 목록 조회 실패를 구분해 안내한다.
- 로딩 중에는 진행 상태를 표시하고 관련 버튼을 비활성화한다.
- 오류가 발생해도 입력한 글이 가능한 한 유지되어야 한다.
- 서버 내부 오류, API 키, 스택 트레이스 등은 사용자 화면에 노출하지 않는다.

### FR-07. 반응형 및 접근성
- 모바일·태블릿·데스크톱 화면에서 레이아웃이 깨지지 않아야 한다.
- 키보드만으로 입력·제출·결과 확인이 가능해야 한다.
- 입력란에는 명확한 label이 있어야 한다.
- 로딩·성공·오류 메시지는 스크린리더가 인식할 수 있도록 적절한 live region을 사용한다.

## 6. 화면 범위
단일 페이지(SPA가 아닌 일반 정적 HTML 페이지)로 구현한다.
1. 상단: Dearly 로고/서비스 설명
2. 일기 작성: 안내 문구, textarea, 글자 수, 교정 버튼
3. 교정 결과: 교정문, 수정 설명, 영어 칭찬 문구
4. 피드백 작성: textarea, 제출 버튼, 공개 안내
5. 최신순 피드백 목록: 전체 항목, 작성 시각, 빈 상태·오류 상태

## 7. 기술 구성
- Front-End: HTML, CSS, Vanilla JavaScript
- Back-End: Node.js, Express
- AI: OpenAI API(서버에서 호출)
- Database: Supabase (PostgreSQL)
- Deployment: Vercel

## 8. 명시적 제외 범위
- 회원가입, 로그인, 소셜 로그인
- 일기 원문 저장·일기장 히스토리
- 친구 추가, 댓글, 좋아요, 팔로우
- 교정 점수·레벨·랭킹·학습 통계
- 음성 입력, 발음 평가, 번역 전용 기능
- 유료 결제 및 구독
- 교사·관리자 대시보드
- 피드백 수정·삭제 UI
- 파일·이미지 첨부
위 기능은 별도 승인 없이 구현하지 않는다.

## 9. 비기능 요구사항 및 제약
- OpenAI 및 Supabase 비밀 키는 서버 환경 변수로 관리한다.
- 일기 원문은 DB에 저장하지 않고 요청 처리 후 폐기한다.
- 공개 피드백은 누구나 볼 수 있으므로 개인정보·민감정보 작성 금지 안내가 필요하다.
- 출력은 XSS에 안전하게 렌더링한다.
- API 입력 길이와 요청 크기를 제한한다.
- 피드백 API 남용 방지를 위한 요청 제한을 적용한다.
- 외부 API 장애 시 사용자가 재시도할 수 있도록 한다.
- Vercel 배포 환경에서 동작해야 한다.

## 10. 완료 기준(Definition of Done)
- [ ] 사용자가 로그인 없이 영어 일기를 입력할 수 있다.
- [ ] 빈 일기와 5,000자 초과 입력이 차단된다.
- [ ] 유효한 일기 요청에 교정문·수정 설명·영어 칭찬이 표시된다.
- [ ] AI API 키가 브라우저 번들·소스에 노출되지 않는다.
- [ ] 로그인 없이 피드백을 등록할 수 있다.
- [ ] 등록한 피드백이 Supabase에 실제 저장된다.
- [ ] 화면 하단에 저장된 피드백 전체가 최신순으로 표시된다.
- [ ] 피드백 내용이 안전한 텍스트로 출력된다.
- [ ] 로딩·빈 목록·성공·실패 상태가 구현된다.
- [ ] 모바일·데스크톱에서 주요 기능을 사용할 수 있다.
- [ ] 필수 테스트를 통과하고 Vercel 배포 설정이 문서화되어 있다.

## 11. 제품 성공 기준
- 첫 화면에서 일기 입력과 교정 요청 방법을 이해할 수 있다.
- 교정 결과를 원문과 구분해 쉽게 읽을 수 있다.
- AI가 원문의 의미를 임의로 바꾸지 않는다.
- 피드백 등록 후 목록에 새 항목이 최신순으로 보인다.
- 주요 오류가 발생했을 때 사용자가 다음 행동을 알 수 있다.
