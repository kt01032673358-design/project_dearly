# AGENTS.md — Dearly 개발 에이전트 작업 규칙

## 1. 프로젝트 목표
Dearly는 학생이 영어 일기를 작성하면 AI가 문법·표현을 교정하고, 학습 의욕을 북돋는 따뜻한 영어 칭찬 한마디를 제공하는 웹 서비스다. 사용자는 계정 생성이나 로그인 없이 일기 기능과 피드백 기능을 이용한다.

제품의 상세 요구사항은 `PRD.md`, 세부 구현 기준은 `docs/`의 문서를 우선 확인한다. 문서끼리 내용이 충돌하면 `PRD.md`의 제품 범위와 이 파일의 보안 규칙을 우선하며, 충돌을 임의로 추측해 해결하지 말고 사용자에게 확인한다.

## 2. 기본 작업 원칙
- 기존 프로젝트 구조와 실행 방식을 먼저 조사한 뒤 수정한다.
- 요구사항에 없는 기능, 페이지, 외부 서비스, 데이터 수집 항목을 임의로 추가하지 않는다.
- HTML, CSS, Vanilla JavaScript를 프런트엔드 기본 기술로 사용한다. 프레임워크나 빌드 도구를 임의 도입하지 않는다.
- 서버는 Node.js와 Express를 사용한다. 배포 환경은 Vercel Serverless Function을 기준으로 구성한다.
- 비밀 키와 서버 전용 설정은 브라우저 코드에 넣지 않는다.
- API 응답, 오류, 로딩, 빈 목록 상태를 모두 구현한다.
- 사용자가 입력한 일기와 피드백을 화면에 표시할 때는 HTML 삽입이 아닌 안전한 텍스트 렌더링을 사용한다.
- 모든 주요 화면은 모바일과 데스크톱에서 사용할 수 있어야 한다.
- 접근성 기본 원칙(명확한 레이블, 키보드 접근, 충분한 대비, 포커스 표시)을 지킨다.
- 실제로 실행·검증하지 않은 항목을 완료했다고 보고하지 않는다.

## 3. 변경 전 확인
1. 저장소의 파일 구조와 `package.json`을 확인한다.
2. 이미 구현된 기능과 환경 변수 이름을 확인한다.
3. Supabase 테이블·정책이 존재하는지 확인한다. 확인 없이 테이블을 중복 생성하지 않는다.
4. UI 참고 이미지가 제공되었다면 색상, 간격, 카드 형태, 타이포그래피를 관찰해 반영한다. 이미지가 없다면 `docs/03-UI-GUIDE.md`의 기본 방향을 따른다.
5. 기존 코드의 동작을 보존하고 변경 범위를 작게 유지한다.

## 4. 보안 및 개인정보 규칙
- `OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`는 서버 환경 변수로만 사용한다.
- `SUPABASE_URL`, `SUPABASE_ANON_KEY`는 공개 설정이지만, 브라우저에 꼭 필요한 경우가 아니면 서버에서 사용한다.
- `SUPABASE_SERVICE_ROLE_KEY`를 HTML, CSS, 프런트엔드 JavaScript, 저장소에 절대 노출하지 않는다.
- OpenAI API를 브라우저에서 직접 호출하지 않는다. 반드시 서버 API를 경유한다.
- 피드백 작성자 이름, 이메일, 학번 등 요구되지 않은 개인정보를 받지 않는다.
- 일기 원문은 기본적으로 DB에 저장하지 않는다. AI 처리 요청에만 사용하고 응답 이후 서버 로그에 원문을 남기지 않는다.
- 피드백은 공개 목록으로 노출되므로 입력 전 안내를 제공하고, 민감정보를 적지 말라고 안내한다.
- 피드백 출력은 XSS를 방지하도록 텍스트로 렌더링한다.
- API 입력값 길이·형식 검증, 요청 크기 제한, 오류 응답 표준화를 적용한다.
- 피드백 생성 API에는 기본적인 요청 제한(rate limiting 또는 Vercel 환경에 맞는 대안)을 적용한다.
- AI 결과는 학습 참고용이며 완벽한 정답을 보장하지 않는다는 안내를 제공한다.

## 5. 구현 규칙
- API 경로, 요청·응답 형식은 `docs/04-API-SPEC.md`를 따른다.
- DB 스키마와 RLS는 `docs/05-DATABASE-SUPABASE.md`를 따른다.
- 기능별 완료 조건은 `docs/06-TESTING-ACCEPTANCE.md`를 따른다.
- 오류는 사용자에게 이해 가능한 한국어 문장으로 표시하고, 개발자용 상세 정보나 비밀 값을 노출하지 않는다.
- 버튼을 누른 뒤 처리 중에는 중복 제출을 방지한다.
- 일기 교정 결과에는 원문, 교정문, 핵심 수정 설명, 칭찬 문구를 구분해 보여준다.
- AI가 반환한 결과는 서버에서 스키마를 검증한 뒤 클라이언트에 전달한다.
- 피드백은 서버에서 저장한 생성 시각을 기준으로 최신순 정렬한다.
- 피드백 등록 성공 후 목록을 다시 불러오거나 새 항목을 목록 맨 위에 반영한다.
